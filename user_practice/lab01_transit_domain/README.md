# Лабораторная работа №1 — Avtobys

## Запуск

Требуется Python 3.12+ и pytest.

```bash
python -m pip install pytest
python -m pytest tests/ -v
```

## Структура

- `domain/route.py` — маршрут, проверка номера, тарифа и остановок.
- `domain/bus.py` — автобус, контроль вместимости и назначение маршрута.
- `domain/card.py` — транспортная карта, баланс, скидка и блокировка.
- `domain/ticket.py` — разовый билет с UUID, временем покупки и одноразовой валидацией.
- `tests/test_domain.py` — тесты бизнес-правил и исключений.

## Архитектурные решения и инварианты

Состояние объектов хранится в атрибутах с префиксом `_`, а публичный доступ предоставляется через `@property`. Денежные значения представлены `Decimal`, чтобы избежать ошибок двоичной арифметики `float`.

Инварианты:

1. Маршрут имеет непустой номер, положительный тариф и минимум две непустые остановки; соседние остановки различаются.
2. Вместимость автобуса находится в диапазоне 10–250; количество пассажиров не бывает отрицательным и не превышает вместимость.
3. Баланс карты неотрицательный; пополнение составляет не менее 100 KZT; заблокированная карта не принимает платежи и пополнения.
4. Коэффициент скидки находится в диапазоне от 0 до 1.
5. Билет имеет положительную цену, действует 60 минут и может быть использован только один раз.

## Контрольные вопросы

1. `Decimal` предпочтительнее `float` для денег, потому что десятичные дроби вроде 0.1 не всегда точно представимы в двоичном формате. Например, `0.1 + 0.2 == 0.3` для `float` обычно дает `False`, а `Decimal("0.1") + Decimal("0.2") == Decimal("0.3")` дает `True`.
2. `@property` дает контролируемый интерфейс чтения атрибута. В сочетании с закрытым соглашением `_attribute` и отсутствием публичного сеттера он помогает не допускать произвольных изменений состояния.
3. Если разрешить `current_passengers = -5`, состояние автобуса станет недопустимым. Последующие расчеты свободных мест и посадки пассажиров могут стать неверными.
4. `InsufficientFundsError` явно сообщает о конкретном нарушении бизнес-правила и позволяет вызывающему коду обработать ошибку отдельно от успешной оплаты. `False` не объясняет причину неуспеха.
