# Лабораторная работа №2 — Composition over Inheritance

## Архитектура

Тариф рассчитывается композицией трех взаимозаменяемых политик: скидки, зоны и времени. `FareCalculator` получает их через конструктор (Dependency Injection) и не зависит от конкретных классов. Новую скидку или коэффициент можно добавить отдельной реализацией протокола, не меняя калькулятор.

## До рефакторинга

```text
BaseFare
├── StudentFare
└── SuburbanFare
    └── StudentSuburbanFare (множественное/ромбовидное наследование)
```

Иерархия смешивает независимые измерения тарифа. При добавлении ветерана, ночного времени и способов оплаты число комбинаций быстро растет. Множественное наследование создает неоднозначность порядка поиска методов (MRO) и усложняет тестирование.

## После рефакторинга

```text
FareCalculator
 ├── DiscountPolicy
 ├── ZonePolicy
 └── TimePolicy

PaymentGate ──delegates to──> PayableCard
```

Компоненты имеют узкие контракты через `Protocol`; калькулятор собирается из конкретных политик во время создания объекта. `PaymentGate` использует переданную карту и не владеет ее жизненным циклом — это ассоциация/агрегация, а не композиция.

## Формула

`(BaseRate × ZoneMultiplier × TimeMultiplier)` — расчетная стоимость до скидки; политика скидки возвращает итоговую стоимость. Все суммы и коэффициенты представлены `Decimal`, округление — `ROUND_HALF_UP` до двух знаков.

## Контрольные вопросы

1. **Агрегация и композиция.** При композиции компонент обычно создается и управляется владельцем и имеет связанный жизненный цикл. При агрегации объект существует независимо и может передаваться между владельцами. В Python это обычно определяется соглашением и кодом, а не специальным синтаксисом языка.
2. **MRO.** При множественном наследовании Python использует порядок разрешения методов (MRO). Изменение порядка базовых классов или добавление метода может изменить вызываемую реализацию, затрудняя диагностику.
3. **Почему тестировать проще.** Каждую политику можно подменить или проверить независимо, а `pytest.mark.parametrize` проверяет комбинации без создания отдельного класса для каждой.
4. **Добавление промокода.** Создается новая политика скидки, реализующая `DiscountPolicy`, и передается в `FareCalculator`. Сам калькулятор изменять не требуется.

## Запуск

```bash
python -m pip install pytest
python -m pytest tests/ -v
```
