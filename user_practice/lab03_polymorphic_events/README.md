# Лабораторная работа №3 — Polymorphic Event Dispatcher

## Архитектура

`events.py` содержит неизменяемые события `BaseTransactionEvent`, `CardTapEvent`, `QrPaymentEvent`, `BluetoothBeepEvent` и `SecurityAlertEvent`. `frozen=True` запрещает изменение полей после создания события.

`EventHandler` задает структурный контракт через `typing.Protocol`. `EventDispatcher` хранит подписки и вызывает обработчики для точного типа события и его базовых типов. Исключение одного обработчика логируется, а остальные обработчики продолжают выполняться.

## Обработчики

- `AuditLogHandler` записывает представление события в `audit_records`.
- `FraudDetectionHandler` отслеживает карту в рамках одного автобуса и создает `SecurityAlertEvent`, если повторное прикладывание произошло менее чем через 120 секунд.
- `PassengerNotifierHandler` имитирует уведомление при оплате.

## Контрольные вопросы

1. **Полиморфный обработчик и `isinstance`.** Вместо центрального набора условных веток диспетчер делегирует работу зарегистрированным объектам. Новые обработчики добавляются без изменения диспетчера.
2. **Неизменяемые события.** `frozen=True` защищает событие от случайной модификации после публикации и делает его содержимое стабильным для нескольких подписчиков.
3. **`Protocol` против наследования.** `Protocol` позволяет объекту соответствовать контракту по наличию метода, не требуя наследоваться от конкретного базового класса.
4. **Приоритет обработчиков.** Можно хранить подписки вместе с числовым приоритетом и вызывать их в отсортированном порядке, например аудит с более высоким приоритетом перед нотификацией.
