## Findings

### G1: Доступ Chrome к файлам владельца

Chrome for Developers описывает `showOpenFilePicker()` и `showDirectoryPicker()` как способы чтения файлов и обхода выбранной папки по явному действию пользователя. Выбор требует secure context и жеста пользователя; он не дает странице скрытый доступ к соседнему пути `OOP-course/`. Руководство Chrome описывает доступ к файлам и папкам как разрешаемый пользователем и указывает, что доступ теряется после закрытия всех вкладок этого origin; при следующем использовании разрешение может понадобиться снова. API нельзя полностью полифиллить: `<input type="file">` лишь приближенно заменяет выбор файла, а `webkitdirectory` — нестандартное приближение выбора папки. [Руководство Chrome по File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access?hl=en), доступ 2026-10-14.

**Статус гипотез:** H1 и H5 частично подтверждены: в Chrome есть явный выбор папки, который потенциально сохраняет отдельность каталога Roman. Не установлено, удовлетворяет ли предполагаемый запуск через `file://` требованиям secure context и загрузки материалов; изученная документация не подтверждает автоматический относительный доступ к соседнему каталогу.

### G2: Варианты изоляции кода студентов

HTML Standard описывает sandboxed iframe как контекст с уникальным opaque origin; скрипты отключены, пока соответствующее разрешение sandbox не возвращено. Стандарт предупреждает: сочетание `allow-scripts` и `allow-same-origin` для встроенного same-origin содержимого позволяет ему удалить sandbox и перезагрузиться за его пределами. Значит, флаги sandbox и разделение origin — существенные проектные переменные. Спецификация worker описывает отдельную глобальную область worker и привязку shared workers к origin; изученный текст не устанавливает worker как границу безопасности и не задает жесткие ограничения CPU/памяти. [HTML iframe sandbox](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox), [HTML workers](https://html.spec.whatwg.org/multipage/workers.html), доступ 2026-10-14.

**Статус гипотез:** H2 остается открытой. Стандарт описывает механизм изоляции origin и конкретное небезопасное сочетание флагов, но этот проход не доказывает безопасность готовой среды проверок в Chrome и ограниченность ее выполнения.

### G3: Локальное хранение прогресса в браузере

Storage Standard включает IndexedDB и `localStorage`, определяет storage buckets и предоставляет `estimate()` для приблизительной оценки использования и квоты. Оценки зависят от реализации; `persist()` запрашивает разрешение `persistent-storage`, поэтому сохранность не гарантируется безусловно. Стандарт допускает очистку данных пользователем. [Storage Standard](https://storage.spec.whatwg.org/), доступ 2026-10-14. В этом проходе не установлены квоты текущего Chrome, поведение приватного режима и восстановление после сброса профиля.

**Статус гипотез:** H3 частично подтверждена: веб-платформа предоставляет локальное хранилище и явный запрос на сохранность данных. Политика хранения и практическое поведение Chrome остаются открытыми решениями Roman.

### G4: Границы оценивания и учебного потока

Одобренная владельцем арифметика сходится: 100 баллов за код + 8 × 25 баллов за теорию + 200 практических баллов = 500. Документация Chrome не может определить распределение трех практических заданий, рубрики, учет экзамена или открытие следующих недель. Эти решения остаются за Roman; исследование может только сопоставить возможности браузера с этими требованиями.

**Статус гипотез:** Сумма H4 подтверждена записью владельца; распределение баллов и экзамен остаются открытыми. Недельный доступ из H5 — продуктовое требование, а не свойство, которое подтверждает документация браузерного API.
