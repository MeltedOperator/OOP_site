## Findings

### C1: Текущие материалы — документы, не локальные web-ресурсы курса

Инвентаризация `OOP-course/` обнаружила 38 файлов, все с расширением `.pdf`, в папках силлабуса, лекций и лабораторных; HTML/CSS/JS/runtime assets в текущем каталоге отсутствуют. Детально считаны метаданные, извлекаемый текст, вложения и URL у силлабуса, лекции №1 и лабораторной №1. Силлабус содержит внешние URL и кликабельные URI-аннотации; у выбранного файла нет вложенных файлов. Выбранные лекция и лабораторная читаются локально и содержат формульные вложения XML; лабораторная №1 указывает Python 3.12+, pytest и Git как среду. Это делает документный offline-доступ правдоподобным, но не предоставляет готовую веб-интеграцию или браузерный runtime. Никакой файл курса не менялся и не преобразовывался.

### C2: `file://` не имеет стандартной гарантии для динамической загрузки приложения

WHATWG URL Standard оставляет происхождение `file:` реализации; «когда есть сомнение» результат opaque. WHATWG Fetch Standard оставляет file-fetch неопределённым и при сомнении возвращает network error. JavaScript module scripts используют CORS fetching. Поэтому не следует основывать `file://` UX на автоматическом `fetch()` каталога, JSON-данных или графа JS-модулей без отдельной проверки целевого Chrome. Настольная справка Chrome описывает выбор между открытием PDF в Chrome и скачиванием для PDF, открытых с сайта; она отдельно не подтверждает поведение для `file://` или extension package. Прямую локальную навигацию к PDF и встроенный показ нужно проверять на целевой конфигурации позже. [WHATWG URL Standard](https://url.spec.whatwg.org/#origin), [WHATWG Fetch Standard](https://fetch.spec.whatwg.org/#file-scheme), [WHATWG HTML: module scripts](https://html.spec.whatwg.org/multipage/scripting.html#script-processing-model), [Chrome Help for desktop: Download a file](https://support.google.com/chrome/answer/95759?hl=en).

### C3: Extension package офлайн, но не тождественен `OOP-course/`

Manifest V3 требует держать исполняемый код внутри package; Chrome предоставляет пакетные ресурсы extension origin. Чтобы extension работал на `file://`-страницах, пользователь отдельно включает доступ к file URLs. Это разрешение не доказывает доступ расширения к произвольным файлам рядом с package. Стандартный файловый выбор может быть вариантом явного доступа, однако просмотренная документация Chrome не подтверждает каталоговый picker в extension page. Следовательно, текущая отдельная папка либо останется внешней и потребует доказанного пользовательского доступа, либо её данные окажутся в package; это взаимоисключающие модели интеграции, а не выбранная нами архитектура. [Chrome Extensions: packaged service worker/code](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/basics), [Chrome Extensions: file URL permission](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions), [Chrome Extensions: web-accessible resources](https://developer.chrome.com/docs/extensions/reference/manifest/web-accessible-resources).

### C4: Материалы предполагают online/account-зависимые действия вне курса

Локальные PDF читаются без сетевого запроса к самим документам, но кликабельные сайты из силлабуса недоступны без сети. Лабораторная №1 требует личный GitHub-репозиторий студента и указывает Python 3.12+, pytest, Git и IDE; если отправка или проверка требует GitHub, такой шаг потребует учетной записи и сети и не укладывается в локальный offline flow как он сформулирован. Сам syllabus указывает Python 3.11+ и набор инструментов, что расходится с точной версией в Lab 1. Полностью локальное выполнение Python и подход к GitHub не установлены. Исследователь не менял документы и не выбирал, должны ли эти пункты стать опциональными, локальными или остаться внешними.
