## Research Plan

### Gather
- Сверить актуальные официальные документы Chrome/WHATWG, которые могут ограничить C1–C6: file-origin storage, unpacked setup, packaged resources, file URL permissions и удаление выбранных storage keys.
- Перевести H1/H2 в наблюдаемые проверки для одного целевого Windows Chrome, одного явно описанного профиля и отключённой сети; не утверждать результаты, которых не наблюдали.
- Определить, какие обязательные ресурсы приложения следует перечислить до прототипного испытания и как отличить локальные требования каркаса от внешних необязательных ссылок.
- Проверить, допускает ли документация исключение каких-либо кандидатов при frozen требованиях; отсутствие документационного ответа оставить как эмпирический вопрос.

### Extract
- Составить минимальную матрицу протокола C1–C6: setup, открытие/проверка PDF, запись и чтение progress, offline restart, Cancel и Confirm reset.
- Для каждого сценария задать предусловия, шаги, наблюдаемый результат и данные для записи (версия Chrome, ОС, профиль, пути, разрешения, сетевой статус), не выбирая лучший вариант.
- Указать безопасную границу reset: отмена ничего не удаляет; подтверждение удаляет только заранее определённые ключи/записи OOPoman; посторонние тестовые данные должны остаться.
- Отделить проверки, пригодные к документированию в TS, от критериев, которые можно закрыть только выполненным прототипом.

### Challenge
- Найти контрпример или официальное ограничение, способное прямо исключить конфигурацию либо изменить её setup-предусловие.
- Проверить, не смешивает ли протокол локальное открытие HTML с доказательством offline cold-start/restart или наличие API с доказательством работающего продукта.
- Проверить изоляцию данных и повторяемость сценариев reset, а также PDF path, не предлагая ослабить frozen требования.
- Сформулировать, достаточно ли двух итераций документированного исследования для перехода к `/tfw-plan`, и что остаётся обязательной реализационной проверкой.
