## 7. Principles 🔒 FROZEN

1. **Сначала понимание:** каждое понятие вводится в контексте задачи, показывается на схеме и затем применяется в коде; паттерны не остаются списком названий.
2. **Русские определения при первом употреблении:** каждый технический термин, который остаётся из источников, получает простое точное объяснение; ненужные темы исключаются.
3. **Примеры на Python:** все шесть страниц недели 3 используют Python по явному выбору владельца. Это не определяет язык будущего runtime и не меняет страницы 1–6.
4. **Локальный безопасный курс:** фиктивные объекты, статические примеры, без исполнения кода, backend, автогрейдинга, сети и стороннего сервиса.
5. **Показать структуру и общение объектов:** локальные UML показывают роли классов и взаимодействия, доступны с пояснением и используются в обучении.

### Risks of Not Researching

Исследование необходимо, чтобы выбрать достоверный пример реального применения ООП; иначе API-сценарий останется непонятным и может быть неточным. Исследовать официальный контракт, учебную пользу паттернов и пригодный sandbox/read-only сценарий, без реальных операций или секретов и без широких обещаний production security. Ложный H1 меняет renderer; ложный H2 требует ясной маркировки preview; ложный H3 меняет учебный кейс. Всё проверяется без подключения к реальному сервису.

### Proposed RESEARCH Focus

Запланировать один сфокусированный RES до TS. Выяснить: (1) как реальные API интеграции используют интерфейсы/адаптеры и какие принципы ООП это показывает; (2) какой официальный sandbox или read-only API подходит как учебный источник и какие ограничения прямо документированы; (3) есть ли конкретная учебная польза у обработки ошибок, повторов или кэширования и как не представить их гарантией безопасности. Использовать официальные первичные источники и выдать рекомендации для лекции/лабораторной 7; не исследовать реальные платежи, учётные записи, комплаенс или production security шире необходимости.

**Leave unchanged:** модуль останется недоступен даже для локальной проверки владельцем, а практическая связь ООП с реальными API не будет объяснена.

Ответ: ограничить RES учебным вопросом и официальными источниками, использовать sandbox/fake data, объяснять термины доступно, держать код полным, но минимальным, дополнительные темы вынести в углубление.
