## 1. Objective

Добавить к девяти теориям и девяти лабораторным OOPoman локальные двухпанельные терминалы Python: студент редактирует код и видит запуск, исключения и строгую практическую обратную связь; комментарии, полные решения и объясняющие аналоги помогают вернуться к заданию. Существующие баллы, ручная взаимопроверка и завершение лабораторий не меняются.

## 2. Scope

### In Scope

- Общий терминальный интерфейс для материалов 1–9, выполнение Python через Pyodide в dedicated Worker, статическое обслуживание локальной копии отдельным localhost launcher и точная документация о неподтверждённых свойствах рантайма.
- Девять теорий: существующие исполняемые строки блоков сохраняются; комментарии добавляются на синтаксисе соответствующего языка (`#` Python, `//` JavaScript). Для существующих JavaScript-примеров теорий модулей 1–2 рядом добавляется отдельный запускаемый Python-блок с `#` комментариями и краткое сравнение классов в обоих языках. JavaScript остаётся сравнительным материалом, а терминал исполняет Python. Слева редактируемый Python-код, справа вывод или ошибка.
- Девять лабораторий: комментированная стартовая заготовка, запуск, проверка всех включённых в терминал практических критериев, показ полного решения по кнопке и тематический аналог с комментариями, объясняющими назначение условий и методов.
- Критерии каждого терминала выводятся из практического задания соответствующей лаборатории и её текущей границы в `course/data.js`; PDF используются как источник, но суженный объём лабораторий 7–9 не расширяется без отдельного решения Roman. Неоднозначные критерии остаются ручными.
- Pyodide и только необходимые локальные runtime assets поставляются версионно и без remote fallback для локальной offline-копии. Launcher обслуживает статические файлы; он не принимает, не исполняет и не сохраняет код.
- Сообщение пользователю, README и North Star точно говорят, что версия и браузерное поведение, изоляция сети и совместимость не прошли эмпирическую проверку. Результаты терминала являются учебной обратной связью и не участвуют в оценке.

### Out of Scope

- Проверка сайта в браузере, запуск Phase A, подтверждение изоляции, совместимости, поддержки браузеров, offline completeness, ресурсного поведения или security sandbox.
- Пересмотр уже принятого решения Pyodide, изменение разрешённой сети для загрузчика, разрешение сетевых вызовов Python-студента, произвольных URL/package installs, backend, database, code upload, аккаунтов или новых средств хранения.
- Изменение существующих строк Python-кода: допустимо только добавлять комментарии Python с `#`. Переформатирование, исправление или перенос существующих строк запрещены.
- Изменение PDF, критериев устной защиты, UML/README-оценки, квиза, чек-листа, баллов, статуса или правил завершения лаборатории.
- Автоматическое подтверждение критериев, для которых материалы не дают однозначного исполняемого наблюдаемого результата.

## 5. Acceptance Criteria

Каждый AC проверяется независимо. `DEFERRED` по эмпирическим runtime утверждениям означает явно непроверенное свойство, не успешную проверку. Никакие локальные source tests не подтверждают браузерную совместимость или изоляцию.

### AC-1: Один общий терминал по всем страницам

У всех 9 лекций и 9 лабораторных есть две панели: редактируемый Python-код и вывод/ошибка. Теория сохраняет семантику примеров; лаборатория предлагает стартовый код, запуск, проверку и учебные действия.
- [ ] Все 18 материалов рендерят terminal controls; запуск выводит stdout, а syntax/runtime error показывает диагностическое сообщение без false success.
- [ ] UI доступен клавиатурой и остаётся usable при узкой ширине.

Gate: `node --test course/terminal.test.js` и `node scripts/build-site.mjs` плюс проверка всех 18 маршрутов в генераторных/source fixtures. Это проверяет код и сборку, не браузер.
Evidence: Pyodide и UI execution в браузере `DEFERRED — владелец разрешил rollout без Phase A; совместимость не проверена`.

### AC-2: Существующие кодовые строки сохранены

- [ ] Для всех существующих code blocks в `course/data.js` зафиксирован до/после текстовый манифест; все прежние исполняемые строки остаются дословно и в прежнем порядке. Разрешены только добавленные комментарии на синтаксисе соответствующего языка (`#` для Python, `//` для JavaScript).

- [ ] Для исходных блоков на страницах, где терминал добавляет обвязку, эта обвязка хранится отдельно и не переписывает исходник.

### AC-3: Проверка лабораторий fail-closed

- [ ] Каждая лабораторная имеет явный набор oracle-backed практических критериев, полученный из текущего задания и соответствующей границы HL. Для каждого критерия заданы входы, ожидаемое наблюдение и negative case.
- [ ] Итог успешен только если запуск завершился без синтаксической/иной ошибки и каждый обязательный терминальный критерий прошёл. Один провал, timeout, malformed result или неполная проверка означает failure и конкретное объяснение.
- [ ] Неоднозначные PDF/архитектурные, документные и устные критерии не считаются автоматически пройденными; пользователь видит, что они остаются на его ответственности/ручной проверке.
- [ ] Обход/изменение пользовательским кодом oracle не может получить green в проверочной логике, насколько это следует из реализуемого клиентского дизайна; если архитектура не позволяет надёжно отделить oracle, терминал честно не заявляет этот критерий автоматизированным.

Gate: позитивные и отрицательные фиксированные fixtures для каждого oracle; мутированные критерии и ошибки должны провалиться. Ни один сценарий не может засчитать успех при одном красном criterion.

- Уважать owner-approved выбор Pyodide dedicated Worker и статический localhost launcher; не возвращать Docker без нового owner decision.

- Отправлять в Worker ограниченный protocol, ограничивать объём вывода и завершать Worker по timeout. Учебные проверки не влияют на прогресс.
- Module 1 is complete under its accepted Phase B return. Implement Modules 2 and 3 together in the combined Phase C after valid Phase B RF; include all six pages in the same approved phase TS, Candidate and phase review, with no intermediate Module 2 completion or Module 3 start gate. For every lab, compare practical criteria against its current site scope and PDF; do not silently restore scope removed from Labs 7–9.
- Установленная в браузере обработка Worker/CSP/network, реальные requests и runtime compatibility остаются неизвестными: source checks могут проверять только заявленную конфигурацию.

## 7. Definition of Failure

- Изменена существующая исполняемая строка любого code block, добавлен комментарий на синтаксисе не того языка, либо JavaScript-теория модулей 1–2 заменена вместо дополнения; затронуты PDF, scoring/progress/completion или расширена граница ЛР 7–9 без решения Roman.
- Ошибка или один непрошедший практический критерий показаны как успех; checker принимает malformed/incomplete output; критерий включён без однозначного oracle.
- Код студента получает предусмотренный сетевой интерфейс/произвольную установку URL, локальный bundle скрыто обращается к удалённым assets, или launcher обрабатывает не статические запросы.
- README/UI/North Star говорят, будто runtime, браузерная совместимость, offline полнота либо изоляция прошли проверку.
- Проспективный VALUE selector/denominator расширен без предшествующего пересмотра и точного owner approval.
