## Findings

### E1: The simplest browser path depends on how students open the site

For the public hosted static copy, Pyodide is a browser-native path: no Docker install, no helper process, and no browser-to-loopback request. Its official distribution is CPython compiled for WebAssembly; pure-Python wheels can be installed and some native-extension packages are ported. The Worker keeps synchronous Python off the UI thread and can be terminated by the owning page on timeout. These properties fit a small beginner console, subject to exact compatibility and behavior checks. Sources: [Pyodide overview](https://pyodide.org/en/stable/), [Pyodide Worker guide](https://pyodide.org/en/latest/usage/webworker.html), [Worker `terminate()`](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate).

For a downloaded local copy opened as `file://`, Pyodide documents browser restrictions on reading local files and recommends serving files over HTTP for development. The default Pyodide filesystem is virtual in-memory MEMFS; browser native filesystem mounting is a separate, experimental capability. Therefore, a plain file-open copy is not the documented simple path. A static-only localhost launcher could serve assets while Python still runs in the browser, but the North Star forbids adding a project-owned server and the Coordinator record says this launcher is not approved. The deployment choice remains open. Sources: [Pyodide FAQ on local files](https://pyodide.org/en/314.0.0/usage/faq.html), [Pyodide filesystem](https://pyodide.org/en/stable/usage/file-system.html), [North Star product boundaries](../../../../../NorthStar.md#product-boundaries).

A basic accidental-misuse profile can be simpler than a hostile-code sandbox: run examples in a Worker, stop and recreate it after a short timeout, cap displayed output, keep each run's Python globals fresh, use only pinned course packages, and do not expose a native-folder picker or mount. The browser still provides Web APIs to Pyodide, so this is not a proof of isolation. The CSP for a Worker is supplied with the worker script response; `connect-src` governs `fetch()`. A Worker must also load the Pyodide runtime and Wasm assets. **Inference:** an exact worker CSP that both loads those assets and prohibits every student-code network request needs a concrete deployment trial; an allowlist that includes an asset origin also allows code in that Worker to request that allowed origin. No such trial ran here. Sources: [CSP in Workers](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy#csp-in-workers), [Worker `fetch()` and `connect-src`](https://developer.mozilla.org/en-US/docs/Web/API/WorkerGlobalScope/fetch), [Pyodide distribution](https://pyodide.org/en/stable/).

The owner's clarification narrows the expected actor to novice accidental misuse, not deliberate attacks. It does not change the governing contract: frozen HL §6 still defines host-file/network access as failure, and §3 still specifies Docker. Replacing that contract requires the authorized amendment route; Researcher cannot reinterpret or edit it. No runtime, CSP or amendment decision is made here. See [HL §3 and §6](../../HL-OOP_20261029-184453_RT.md).

### E3: Docker and browser runner expose different setup trade-offs

Docker keeps native CPython and explicit container CPU/memory/process controls, but the learner needs Docker and the website needs a local helper with authority to request containers. The project documents no loopback API or Docker CLI on this host, so no working baseline could be trialed. Pyodide avoids that install/helper route for a hosted page, but needs module Worker support, pinned static runtime assets and a compatible CSP/asset origin; it is a narrower Python environment and the local direct-open route remains unresolved. These are distinct configurations rather than a drop-in runtime swap. Documentary sources: [Docker security](https://docs.docker.com/engine/security/), [Docker resource constraints](https://docs.docker.com/engine/containers/resource_constraints/), [Pyodide browser guide](https://pyodide.org/en/stable/usage/index.html). No runtime start, code execution, network canary, timing or resource measurement occurred.
