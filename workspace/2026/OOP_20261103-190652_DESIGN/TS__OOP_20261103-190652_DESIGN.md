## 1. Objective

Обновить локальный интерфейс OOPoman так, чтобы студенту было проще читать примеры кода, понимать подсказки и собственный учебный прогресс, а после завершения всех трёх модулей и сдачи экзамена — скачать соответствующий JPG-сертификат. Сохранить текущий курс, его учебный поток и раздельные правила курса и экзамена.

## 2. Scope

### In Scope

- Обновить главную страницу текстом владельца: «Иванов Роман, студент 2 курса, величайший».
- Добавить статическую, читаемую подсветку JavaScript и Python кода в текущих примерах. Язык размечается явно; формула, ожидаемый вывод и неизвестный тип остаются обычным текстом. Для различения категорий не полагаться только на оттенок цвета. Не изображать проверку синтаксиса.
- Добавить понятные значки лампочки к подсказкам теории и лабораторных, сохранив доступный текстовый смысл.
- Освежить оформление: неброские геометрические детали фона, выразительные, но согласованные акценты модулей, понятные состояния наведения/нажатия/фокуса и короткие анимации с учётом `prefers-reduced-motion`.
- Отображать прогресс курса раздельно: завершение каждого из 3 модулей, число завершённых лабораторных и доступный результат экзамена (балл и статус). Добавить текстовые числовые эквиваленты progress bars.
- Объяснить в описании экзамена, что сертификат доступен после завершения всех 3 модулей и успешной сдачи экзамена.
- После принятия независимого задания EXAM сверить только его разрешённый итоговый результат и ровно определить авторитетный локальный сигнал успешной сдачи. Показ сертификата разрешён только если это условие и завершение всех 3 модулей одновременно подтверждаются. Отсутствующие, невалидные или неизвестные данные не считаются выполненным условием.
- Сопоставить три экзаменационных имени с неизменёнными файлами:
  - Арсений Мухитов → `OOP-course/certificates/certificate_arseniy.jpg`
  - Жасулан Куандыков → `OOP-course/certificates/certificate_jasulan.jpg`
  - Санжар Аубакиров → `OOP-course/certificates/certificate_sanjar.jpg`
- Исправить вариант имени «Саржан» на «Санжар» только в уже принятом EXAM отображении имени. Не менять вычисление балла, состав вопросов или правила прохождения экзамена.
- Добавить доступную кнопку возврата вверх на длинных страницах.
- До начала исполнения снять SHA-256 трёх предоставленных JPG и затем подтвердить, что файлы включены без изменения байтов.

### Out of Scope

- Публикация, сервер, аккаунты, проверка личности, криптографическая защита или удостоверение с заявленной неизменяемостью.
- Переписывание курса, переход на SPA, изменение структуры модулей или отдельные фазы B/C.
- Полноценный редактируемый IDE-интерфейс, автодополнение, live parsing, live syntax diagnostics и изменение Python Worker.
- Изменение схемы начисления баллов, прохождения лабораторных/модулей или экзаменационного pass rule.
- Изменение JPG, других курсовых материалов, несвязанных лабораторных проектов и сторонних файлов.
- Добавление или запуск новых автоматизированных тестов. Проверка результата фиксируется существующими командами и ручными наблюдениями.
- Старт исполнителя до принятого результата задания EXAM и до сверки его точного exam-state/pass contract.

## 5. Acceptance Criteria

Each AC is independently verifiable; dependencies use `[depends: AC-X]`. Gate is synthetic verification; Evidence is real-environment verification.

### AC-1: Readable static code examples

All JavaScript and Python source examples use explicit language identity and readable token categories for keywords, declarations/names, strings/text and other visible syntax. `constructor` is styled as a method name. Formula, expected output and unknown-language content remain unhighlighted. Preserve text escaping and source content. Use at least one non-color cue for category distinction. No editor or syntax-validity claim is added.
- [ ] Compare representative JS and Python examples including strings, a Python f-string, method/class declarations and comments at normal page size; confirm formula/output/fallback are plain.
- [ ] Check foreground/background contrast on every code background and inspect that token categories remain distinguishable without relying only on color.
- [ ] Confirm examples remain static and cannot imply live diagnostics.

Gate: inspect generated markup/styles and manually render representative lesson and lab pages in the target local browser after implementation.
Evidence: screenshot or exact page/viewport observations, token cases, selected backgrounds, and any unsupported constructs; no formal conformance claim from a small sample.

### AC-2: Truthful progress display

Homepage and progress view show module completion, completed-lab count, and the exam score/status as separately labeled values. Progress bars have text equivalents and reflect the existing stored course data plus the accepted EXAM result. Missing or malformed exam state is labeled unavailable/not passed and never represented as success.
- [ ] Compare displayed values against the underlying local state for incomplete, partially complete and complete course cases.
- [ ] Confirm exam score and pass status use the accepted EXAM source without changing exam scoring or course progress.

Gate: inspect calculations and manually compare rendered values to known stored-state examples.
Evidence: recorded input state, displayed module/lab/exam values, and outcome for missing/invalid state.

## 6. Technical Guidance

- Iteration-2 RES found Prism and Highlight.js suitable candidates for static, explicitly labeled JS/Python spans. Choose a local method proportionate to this small course; justify any heavier editor/build setup in RF.
- The H1 rendered-category check was stopped by the owner's instruction because available tools could not view the temporary sample. H1 remains partially supported. The Executor/Reviewer must inspect the actual implementation in the local course and record only what was observed; no prior visual sample is claimed.
- Use a plain fallback for formulas, output and unknown blocks. Preserve escaped code text and avoid naive keyword substring matching; treat f-strings carefully.
- Candidate light accents individually pass calculated background contrast, but pairwise color-only category distinction was not established. Add a redundant cue such as weight or another readable structural style and inspect the rendered result.
- Treat all local browser state as editable local course state. Do not imply identity verification, official validity, server validation or tamper resistance.
- Required dependency before Executor launch: accepted current EXAM result, exact exam-state/pass rule, and unique `examNamePath`; stop and ask if any cannot be established.

## 7. Definition of Failure

- A code block is assigned the wrong language, a formula/output is styled as source, or source text is corrupted/unsafe.
- Token categories cannot be distinguished at normal size or rely only on color; a small research sample is described as proof of full-corpus behavior.
- The UI claims syntax validation without a configured real parser/linter.
- Progress disagrees with the source state or hides an unknown exam result as success.
- A certificate is downloadable after only one completion condition, for the wrong name, from a changed JPG, or without the accepted EXAM pass predicate.
- Exam questions, scores, thresholds, course progression or module completion behavior change.
- UI changes reduce keyboard, screen-reader text, reduced-motion or responsive usability.
- Site no longer functions in the existing local course flow or scope expands into a new platform/server.
